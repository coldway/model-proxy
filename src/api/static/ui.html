API 接入指南

兼容 OpenAI SDK，上游服务可直接替换 base_url 接入

基本信息

Base URL
API Key任意值（如 "unused"）
核心接口POST /v1/chat/completions
模型列表GET /v1/models
使用量GET /v1/usage
协议完全兼容 OpenAI Chat Completions API，支持流式 (SSE) 和非流式

模型选择

"auto"系统按厂商优先级 → 模型优先级自动选择最优可用模型（推荐）
指定模型传入具体模型名，如 "gemini-2.5-flash"、"llama-3.3-70b-versatile"
当指定模型额度耗尽时返回 429；使用 auto 模式时会自动降级到下一个可用模型。

请求格式

POST /v1/chat/completions
{
  "model": "auto",
  "messages": [
    {"role": "system", "content": "你是一个助手"},
    {"role": "user", "content": "你好"}
  ],
  "temperature": 0.7,
  "max_tokens": 2048,
  "stream": false,
  "session_id": "my-task-001",
  "mode": "plan",
  "force": false,
  "sandbox": "enabled"
}
session_id 为可选字段。传入后首次请求自动绑定模型，后续相同 session_id 的请求将路由到同一模型（1小时过期）。不传则按正常路由逻辑处理。
mode / force / sandbox 为 Cursor 厂商专用扩展字段，详见下方「Cursor Agent CLI」章节。

响应格式

非流式响应
{
  "id": "chatcmpl-xxx",
  "object": "chat.completion",
  "model": "gemini-2.5-flash",
  "choices": [{
    "index": 0,
    "message": {"role": "assistant", "content": "你好！"},
    "finish_reason": "stop"
  }],
  "usage": {"prompt_tokens": 10, "completion_tokens": 5, "total_tokens": 15},
  "proxy_info": {
    "provider": "google",
    "trace_id": "a1b2c3d4e5f6",
    "latency_ms": 1230.5,
    "route_strategy": "priority",
    "session_id": "my-task-001",
    "bound_model": "google:gemini-2.5-flash"
  }
}
流式响应（SSE，最后一条 chunk）
{
  "id": "chatcmpl-xxx",
  "object": "chat.completion.chunk",
  "model": "gemini-2.5-flash",
  "choices": [{
    "index": 0,
    "delta": {},
    "finish_reason": "stop"
  }],
  "proxy_info": {
    "provider": "google",
    "trace_id": "a1b2c3d4e5f6",
    "latency_ms": 1230.5,
    "route_strategy": "priority",
    "session_id": "my-task-001",
    "bound_model": "google:gemini-2.5-flash"
  }
}
proxy_info 为 model-proxy 附加的路由元数据（非流式直接返回，流式在最后一条 chunk 中返回）：
provider实际处理请求的厂商 ID
trace_id请求追踪 ID，可用于日志关联排障
latency_ms端到端推理耗时（毫秒）
route_strategy路由策略：direct / priority / round_robin / fallback
session_id传入的会话 ID（未传入时不返回此字段）
bound_model当前 session_id 绑定的模型，格式 provider:model（未绑定时不返回）

Cursor Agent CLI（plan / ask / agent）

当请求路由到 cursor 厂商时，可通过扩展字段控制 Cursor CLI 的执行模式。 推荐模型：auto、composer-2.5。

mode执行模式：plan（只读规划）、ask（只读问答）、agent（默认，可改代码/执行命令）
force是否强制执行命令（对应 CLI --force）；plan / ask 下自动忽略
sandbox沙箱模式："enabled" / "disabled"（对应 CLI --sandbox）
Plan 模式请求示例
{
  "model": "auto",
  "messages": [
    {"role": "user", "content": "分析这个项目的架构并提出重构方案"}
  ],
  "mode": "plan",
  "sandbox": "enabled"
}
前置条件：本机已安装 Cursor CLI（agent --version）且已登录（agent login）。 其他厂商会忽略 mode / force / sandbox 字段。

会话模型绑定（Session Affinity）

                        

                            通过 session_id 参数，可以让同一会话内的所有请求使用相同的模型，确保对话连贯性。
                        

                        

                            
首次请求携带 session_id，正常路由选模型，成功后自动绑定

                            
后续请求携带相同 session_id，优先调用绑定的模型

                            
绑定模型失败自动降级到正常路由重试其他模型，成功后更新绑定

                            
绑定过期1 小时后自动失效，下次请求重新路由并绑定

                            
不传 session_id按正常路由逻辑处理（auto / 指定模型）

                            
管理 APIGET /mp/api/session-bindings 查看 | DELETE /mp/api/session-bindings/clear 重置

                        

                    


                    

                        
错误码

                        

                            
413请求 payload 超出目标模型的大小限制（自动路由时会尝试切换其他模型）

                            
429模型额度用尽（指定模型时）或全部限流

                            
404指定的模型不存在或未启用

                            
503所有模型均不可用（未配置或全部熔断）

                            
500推理服务内部错误

                        

                    


                    

                        
Payload 大小自适应

                        

                            model-proxy 内置动态 payload 上限检测机制。当某模型返回 413 Payload Too Large 时，
                            自动记录该模型的 payload 上限，后续请求会根据 payload 大小跳过超限模型。
                        

                        

                            
触发条件模型厂商返回 HTTP 413

                            
行为记录触发 413 的 payload 大小为该模型上限；相同/更大 payload 自动跳过该模型

                            
收敛更小的 payload 再次 413 → 上限自动下调；成功处理更大 payload → 自动清除限制

                            
auto 模式自动切换到 payload 上限更高的其他模型，对调用方透明

                            
管理 APIGET /mp/api/payload-limits 查看 | DELETE /mp/api/payload-limits/clear 重置

                        

                        

                            持久化到 data/payload_limits.yaml，服务重启后自动加载。
